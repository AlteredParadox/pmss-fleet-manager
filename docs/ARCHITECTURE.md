# pmss-fleet-manager architecture

Single Go binary. One central instance polls every Pulsed Media box over SSH as the
tenant user (no root, nothing installed on the boxes) and serves a web dashboard.

```
browser  <-- HTTP/JSON + SSE -->  pmss-fleet-manager  <-- SSH -->  box (tenant shell)
                                     |  sqlite                 |-- probe.sh  (quota, traffic, cgroup, /proc)
                                     |                         |-- 127.0.0.1:<port>  qBittorrent Web API
                                     |                         `-- /run/user/<uid>/docker.sock  Docker API
```

## Data sources on a PMSS box (tenant-readable)

| Need | Source | Notes |
|---|---|---|
| disk used / quota / inodes | `quota -v -w` (live) or `~/.quota` (1 min cron) | KiB blocks; hard limit is 1.25x soft |
| traffic, rolling 30 days | `~/.trafficData` (egress), `~/.trafficDataIngress` (ingress) | PHP `serialize()`: `{raw:{month,week,day,hour,15min} MiB, daily:{Y/m/d: MiB}}`, refreshed :25/:55 |
| traffic limit | `~/.trafficLimit` + `~/.bonusTraffic` (GiB) | effective = limit + min(bonus, limit); 0 = unlimited |
| throttled | `~/.throttle` exists | set hourly by PMSS when over limit |
| ram / cpu / pids | cgroup slice `user-<uid>.slice` (v1 controllers, v2 fallback): usage, `memory.stat` rss/cache split, OOM-kill counter | pressure is process memory, not the charged figure (page cache); CPU% from usage delta between polls |
| account config | `~/.config/pmss-user.json` | quota GiB, ramMiB, dockerEnabled, trafficCapMbit |
| host | `/proc/uptime`, `/proc/loadavg`, `/proc/stat` (busy / iowait / steal over the poll, as PMSS's live-stats panel counts them) with iowait also averaged over the dashboard's own polls of the last 15 / 30 / 60 min (a ring in the poller: a restart or edit starts the windows over), `/proc/meminfo`, `/proc/cpuinfo`, `/dev/dri/renderD*`, `/etc/debian_version`, `/etc/os-release`, `uname -m`, `systemd-detect-virt`, the account count in `/etc/passwd` (UIDs above 1000 except nobody, for the hardware catalogue), and only while that catalogue integration is on, the clock and storage measured yabs.sh's way (last `cpu MHz` of `/proc/cpuinfo`; `stat -f` over the local filesystems in `/proc/mounts`, df as the fallback), `/etc/seedbox/config/version`, `df /home`, PMSS's live-stats rings `/var/lib/pmss/public/node-live.json` and `/var/lib/pmss/live/<user>.json` (inventory cadence; its ADR 0126) | shared host, informational |
| WebUI connection owner | after every new tunnel connection to the port, `EstablishedScript` lists the established sockets on that port (`/proc/net/tcp{,6}` state 01, else `ss -Htnp state established`) and every one must be owned by this uid (`probe.EstablishedOwner`), before any byte is written; a verified connection's peer is fixed so pooling is safe; where the box shows no established sockets at all (socket-table privacy hosts) the listener check alone applies | closes the check-then-connect gap of the listener check: a co-tenant who grabs the port between check and connect accepts a connection that is then refused; pooled connections are dropped when the client process changes |
| WebUI port owner | `/proc/net/tcp` and `/proc/net/tcp6` listening rows (uid per socket); `ss -tlnp` where PMSS has made those tables root-only (own sockets carry the uid, any other listener is foreign) | the credential gate: WebUI logins only when the port is bound by this account alone; re-read live before every action that sends credentials (client stop, pause/resume all, per-torrent stop/start/remove, add, DHT/PeX/LSD toggles) |
| client install state | `~/bin/qbittorrent-nox --version` (only when the binary's `stat -L '%s %Y %Z %i'` changed since the last answer, passed back as `PMSS_QBT_SEEN`: the call writes a start/exit block into the user's qBittorrent log), `~/bin/qbt-start`, `crontab -l` | drives "update available", "restart to apply" and the autostart hint |
| torrents | qBittorrent Web API over SSH tunnel (`sync/maindata` incrementally: the first call fetches everything, later ones send the last response id and merge the delta; the view resets whenever the client process may have changed; at most 20 000 torrents per box, decoded as a stream, more is an error), `app/version` | user-installed `~/bin/qbittorrent-nox`; port from `~/.config/qBittorrent/qBittorrent.conf` or box setting. Writes on request: `torrents/stop|start|pause|resume|delete|add`, `app/shutdown` |
| rTorrent | XML-RPC over SCGI on the tenant's unix socket (`~/.rtorrent.socket`, from `network.scgi.open_local` in `~/.rtorrent.rc`/`.rtorrent.rc.custom`, or the box setting), dialed through the SSH channel; one `system.multicall` for version/rates/listen port/DHT and one `d.multicall2` on the main view per poll (≤ 20 000 rows, streamed decode behind byte/element/depth caps, invalid UTF-8 repaired). Writes on request: `d.stop`+`d.close`, `d.open`+`d.start`, `d.erase`, `load.start`/`load.raw_start` (and the stopped variants); remove-with-data erases, then runs `rm -rf` on the box only after the box itself resolved both paths and found the download root strictly inside the home and the target strictly inside the root | PMSS's own rTorrent (0.9.8 or the client store's 0.16.x), started by the panel's watchdog; no install/start/stop from here |
| DHT / PeX / LSD, listen port | `app/preferences` every poll; `app/setPreferences` on toggle | only the three booleans are written |
| incoming connectivity | `server_state.connection_status` from `sync/maindata` | connected / firewalled / disconnected; the time it was first seen not connected is carried in state, and the alert waits ten minutes because a fresh client says firewalled until a peer dials in; a client with no torrents is not timed at all (no peer can learn its port, so the flag never clears) |
| containers | Docker Engine API on `/run/user/<uid>/docker.sock` over SSH | rootless dockerd |
| log files | `find` over a fixed list of directories under the home (`*.log`, `*.log.*`, `*.txt`, 40 per directory) plus a few single files, as size/mtime/relative path; on demand `tail -n 300 \| tail -c 256K` of one listed path, the path quoted into the script body (never a command line); container output via the Engine API `/containers/{id}/logs` with the stream framing removed | read-only; the API only reads a path the last probe listed, and the script re-checks it on the box (relative, no `..`, regular file) |
| own processes / applications | `ps -u <uid>` (pid, ppid, rss, cumulative CPU seconds, age, comm; args separately, clipped), `ss -tlnp` for port -> own pid | hidepid=2 means only the account's processes are visible anyway; the probe's own shell and children are dropped; `internal/collect/apps.go` groups them into apps by comm/args and derives CPU% from two samples of the same pid; the watch list lives in `boxes.apps_watch` and is edited only through its own endpoint |
| usage by directory | `du` on top-level home entries, low priority, every few hours | optional, heavy; the 500 largest entries are kept, the rest summed into one |
| plan / price / renewal / PM usage | Pulsed Media customer API `https://pulsedmedia.com/remote/pmapi-feed.php` (`X-API-Key`) | optional; synced every 6 h and on demand; cached in the settings table; matched to boxes by host+user, then unique host, then unique user. Manual plan / renewal on a box override it; datacenter is manual only |
| plan I/O and CPU priority | the public campaign page `https://pulsedmedia.com/eternal-vainamoinen.php` (every plan card prints "I/O: Standard (100)" and "4 CPU cores · Performance (500)"; the tier ladder is on the wiki's resource-tiers page) | the customer API does not carry them; the page is read on demand (settings, or a box whose priorities are unknown) and on its own only while an API key is set, when a box's matched product is missing from the last read (once per product name, a failed read retried at the next occasion, automatic reads at least an hour apart); cached in the settings table; each box resolves typed-in weights first (`boxes.io_weight` / `cpu_weight`), then the listing for its plan name (the typed plan, else the API product; compared word by word with the campaign prefix dropped, the longest listing whose words open the name wins, since the API says "Eternal Väinämöinen - Seedbox 1TB R5 10G" and "Dragon-R Trophy 100 Years GiveAway"; a name listed twice with different priorities is ambiguous and shows nothing). The page is untrusted: body bounded at 2 MiB, cards read by their fixed label text only, names cleaned and clipped, weights checked against the 1..10000 scale and relabelled from the ladder, the same transport rules as the catalogue client below |
| host hardware catalogue | pmdb.fyi `GET /api/servers`, `GET /api/config`, `GET /api/nodes/<host>?limit=1` (all public) and `POST /api/servers/raw` (public, carries the submission identifier) | opt-in (settings checkbox + identifier); outbound: hosts are deduplicated by catalogue key across boxes and each is submitted once under the identifier (hostname, CPU model, cores, clock and storage measured yabs.sh's way so they agree with YABS uploads, RAM, swap, KVM, distro, kernel, arch, account count, the box's plan when the catalogue's config lists it), then again only when the dashboard's own row changes, after 30 days or under a new identifier (receipts in `pmdb_submissions`); a row lacking an optional value reads the catalogue's current row first and repeats its numbers/booleans and filtered strings, or skips the host (the catalogue replaces rows whole); at most 25 submission attempts per 10 min; a failed submission retried after an hour; runs after an inventory (fetching the list only while a host is due, at most every 10 min), every 6 h and on demand (both always fetch unless a hold applies). Responses are untrusted: body, row count and header size bounded in entity bytes before content decoding (compression never asked for, a compressed answer refused; transfer framing bounded by Go's parser and the deadline), the list streamed and read for DNS-shaped names only (odd rows skipped, null and trailing bytes refused), a submission's answer its status alone (body never read), no text from any response kept, logged or shown (errors are fixed messages or status codes; a row string travels back to the catalogue only through its own text rule), one HTTP/1.1 connection per request, never reused whatever the server answers (nothing after a declared answer can reach net/http's idle-connection log line; no HTTP/2 framing or deadline-less clean-up writes; ALPN offers http/1.1 only), redirects refused, one run under a total time budget, holds after a rate limit or service failure |
| box-to-box copy or move | `rsync -rt` over ssh from the source box straight to the destination, detached on the source (`~/.config/pmss-fleet-manager/transfers/<job>/`: a fresh ed25519 key, the runner, bounded progress and error files), the dashboard adding one `restrict,expiry-time,command="/usr/bin/rrsync -wo -no-del -munge '<dir>'"` line to the destination's `authorized_keys` for the job and removing it after; status read every 5 s; a job finishes on the runner's exit code alone. A move is the same runner with one more step after exit code 0 only (rsync's per-file whole-file checksum is the check; no second pass, which could not reuse the key anyway): `find -type f ! -newer started_at -delete`, then the empty directories; symlinks, special files, files modified since the copy started and anything undeletable stay and are counted (`move` file: `moved` / `left N`); the step ignores TERM | the destination is a new directory the job creates, or an existing one (files kept with `--ignore-existing`, or replaced on rsync's size+mtime check); never the home, `~/.ssh`, `~/.config` or the control directory, and an existing one may hold no symlink and no file with a name outside it (a link already there is a way out of the directory for a hostile source: a symlink via `--partial-dir`, a hard link's other name via `--inplace`; the scan counts a file's names inside the folder against its link count, so links within the folder pass; it is a setup-time check); one active copy per source box and per destination account; a move may not use the keep rule, nothing is copied into a running move's source account, and a move does not start from an account still receiving a copy (the removal deletes by timestamp, not from rsync's file list) |

PMSS "month" counters are a rolling 30-day window, not a billing cycle. The UI says so.

## Packages

- `cmd/pmss-fleet-manager` flags, wiring, graceful shutdown
- `internal/store` SQLite (modernc, pure Go): boxes, settings, alerts, per-box caches
- `internal/secrets` optional encryption of the stored credentials (HKDF-SHA256 → AES-256-GCM, column name as additional data) under a secret from the environment or a file
- `internal/sshx` SSH client (TOFU host keys, bounded dial/run), unix/tcp dialer; reconnects are the poller's job
- `internal/phpserial` minimal PHP `unserialize`
- `internal/probe` the remote shell probe and its parser -> `probe.Snapshot`; the probe's stdout is budgeted at 6 MiB (`collect.probeOutputLimit`, an overrun fails the poll) and the parsers bound their rows while reading. The probe has two cadences: every poll measures (load, memory, quota, traffic, cgroup, processes, listeners); the inventory sections (host identity, the installed qBittorrent binary and its version, the start helper, the crontab, the log catalogue) run on a poller's first poll, every 15 minutes, and on demand (a refresh, an install or autostart action, the logs tab finding its listing older than ten minutes), and the poller carries the last inventory across the polls in between
- `internal/qbt` qBittorrent Web API client over an arbitrary dialer
- `internal/dockerx` minimal Docker Engine API client over an arbitrary dialer
- `internal/pmapi` Pulsed Media customer API client (services feed)
- `internal/pmplans` the plan page reader (I/O and CPU priority per plan)
- `internal/pmdb` pmdb.fyi hardware catalogue client (public list, config and node row; raw submission under an identifier)
- `internal/collect` per-box poll loop, rate math, state cache, event bus. Every change to a box's live state goes through `Manager.commit`, which matches the services feed of that moment, assigns a fleet-wide revision, stores, runs the alert hooks and hands the event to the bus in that one order; `/api/state` reports the revision it was taken at, and the page merges snapshots and events by revision (a state below what it holds is dropped), so a stream that opens while a snapshot is in flight loses nothing. Everything measured on a box belongs to its generation (SSH host, port, account and pinned host key): an edit that keeps them carries the live state over, one that moves the record or forgets the pin starts from the record alone, drops the cached state and du (rows are tagged and refused across generations anyway) and resolves the old machine's alerts; actions that use facts read from the box (UID, container IDs, log list, the panel-managed marker) wait for the first complete probe of the generation (`BoxState.Ready`, HTTP 409 until then)
- `internal/alerts` rule evaluation, dedup, auto-resolve, ack; per-container alerts capped at 20 per box plus one aggregate (an open one still failing is always kept), resolved rows bounded per box by the store's prune
- `internal/api` HTTP JSON API, SSE, embedded static UI
- `internal/web` the vanilla JS/CSS frontend (no build step)

## Security

- Binds to 127.0.0.1 by default; optional HTTP basic auth (`-auth user:pass`).
- Box credentials live in the SQLite file (0600), in plain text or, with `PMSS_SECRET` set, as AES-256-GCM ciphertext sealed and opened at the store boundary (`internal/secrets`; plaintext rows are resealed at open, a missing or different secret refuses to start). Prefer SSH keys or the agent over passwords.
- Host keys are pinned on first connect (known_hosts style, stored per box).
- A box-to-box copy's key lives on the source box only and is good for one job: forced into the system's `rrsync` (root-owned, checked) confined to the chosen directory, write-only, deletes off, symlinks munged, 30 minutes. The source holds the key, so a source that turned hostile is the threat model: it can write anything inside that directory but nothing outside it, which is why an existing destination with a symlink inside, or a file with a name outside it, is refused (through either, `--partial-dir` or `--inplace` would reach the link's other name), and the home, `~/.ssh` and the control directory are never destinations.
